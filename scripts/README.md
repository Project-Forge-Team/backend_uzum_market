# scripts/ — сквозная проверка контракта

## e2e.py

55 проверок всего API против **живого** сервера: каталог, фильтры/фасеты,
авторизация (cookie+CSRF), магазин, CRUD товара, отзывы, заказы (включая
недостаток остатка и возврат при отмене), загрузки, demo/reset.

```bash
# локально (сервер уже запущен):
python3 scripts/e2e.py http://127.0.0.1:8000

# после деплоя:
UZUM_BASE_URL=https://<ваш-домен> python3 scripts/e2e.py
```

Только стандартная библиотека — внешних зависимостей нет. Ничего не устанавливает,
в конце сам возвращает БД к сид-состоянию (`POST /api/demo/reset/`).

Особенности:

- Скрипт делает ~8 POST на auth-эндпоинты, а лимит — 10/мин с IP (§4 ТЗ):
  не запускайте чаще раза в минуту (при 429 скрипт сам подождёт и повторит).
- Требует, чтобы сид залит (иначе проверка «categories = 10» не пройдёт):
  `python manage.py seed --reset`.
- Код возврата: `0` — все 55 прошли, `1` — есть падения (удобно в CI).

тестом `apps.orders.tests.CreateOrderTests.test_service_level_stock_race`
и проверяется отдельно двумя параллельными curl.
